# 豫鑫 API 网关 · 前端运营配置手册（0 基础版）

> 适用对象：完全没接触过本系统的运营/管理人员。
> 读完你能做到：登录后台 → 接入模型 → 定价 → 配支付收款 → 建用户验证 → 日常运营（用户/兑换码/订阅/公告）→ 看监控排故障。
> 版本：v1.2.22-yuxin-wallet-pay · 实测日期 2026-08-19 · 所有页面均真实打开核对（截图 76 张）。
>
> **使用方法**：按章节顺序做。这是"业务展开顺序"，不是字典——先做第 1 章再做第 2 章。每章结尾有【验证】，确认这一步真的生效了再往下走。

## 第 0 章 · 先搞懂：你要管的是什么

### 0.1 一句话
豫鑫 API 网关是一个**卖 AI 模型调用额度**的平台。你的工作是：
1. 接入上游模型（让平台有模型可调）
2. 定价格（决定收用户多少钱）
3. 配支付（让用户能充值）
4. 管用户（建号、调额度、处理问题）

### 0.2 怎么登录管理后台
1. 浏览器打开：https://ai.yuxin.yun
2. 点右上角「登录」，输入管理员账号密码
3. 登录后，**左侧边栏会多出一个「管理员」分组**——只有管理员能看到
4. 【验证】能看到侧边栏「管理员」分组（渠道/模型/用户/兑换码/订阅/系统信息/系统设置）= 登录成功且有管理员权限

> ⚠️ **如果看不到「管理员」分组**：说明你登录的是普通账号，不是管理员。换管理员账号登录。

### 0.3 后台地图（先有个整体印象）
```
左侧边栏「管理员」分组
├─ 渠道        ← 接上游模型（第1章）
├─ 模型        ← 管模型元数据（第1章）
├─ 用户        ← 管账号（第5章）
├─ 兑换码      ← 发卡密（第5章）
├─ 订阅        ← 套餐（第5章）
├─ 系统信息    ← 看服务器状态（第6章）
└─ 系统设置    ← 大配置中心（第2/3/4章）
   ├─ 站点与品牌      改站名/Logo/协议
   ├─ 身份验证        注册/登录/OAuth/人机验证
   ├─ 计费与支付      定价/支付网关（重点）
   ├─ 模型与路由      调度/重试/智能路由
   ├─ 安全与限制      限流/敏感词/SSRF
   ├─ 控制台内容      公告/FAQ/API地址
   └─ 运维            SMTP邮件/日志/性能
```

## 第 1 章 · 接入模型渠道（让平台有模型可调）

**这一步干什么**：把上游 AI 模型供应商（阿里云、DeepSeek 等）接进来，平台才有模型可以卖给用户。

### 1.1 建一个渠道
1. 点侧边栏「渠道」
2. 点右上角「创建渠道」
3. 填表单（四段）：

**基本信息**
| 字段 | 怎么填 | 说明 |
|---|---|---|
| 类型 * | 选上游供应商（如"阿里百炼"、"OpenAI"、"DeepSeek"）| 决定对接协议 |
| 名称 * | 起个好认的名字（如"阿里云"）| 给你自己看的 |
| 已启用 | 打开 | 关了就不参与调度 |
| API 地址 | 填上游地址（阿里百炼是 `https://dashscope.aliyuncs.com`）| ⚠️ 不要带 `/v1` 或末尾斜杠 |

**凭证**
| 字段 | 怎么填 |
|---|---|
| 添加模式 | 单密钥（一个 key）或多密钥 |
| API 密钥 * | 上游供应商给你的 key（去上游平台拿）|

**模型与分组**
| 字段 | 怎么填 |
|---|---|
| 模型 * | 点「填充所有模型」或勾选这个渠道支持的模型 |
| 分组 * | 选 `default`（默认用户组能用）|

**高级设置**（一般先用默认）
- 优先级：数值大的优先被选中（默认 0）
- 权重：负载均衡，越高请求越多（默认 100）

4. 点保存

### 1.2 测试渠道能不能用（必做）
1. 回到渠道列表，找到刚建的渠道卡片
2. 点卡片上的**闪电图标（测试连接）**
3. 【验证】卡片显示"响应 X 秒"和"上次测试时间" = 渠道通了
4. 如果测试失败：检查 API 密钥对不对、API 地址对不对、模型选了没有

> 💡 **现有渠道参考**：当前平台有 2 个渠道——阿里云（#11，响应 1.6 秒，正常）、联通云（#1，响应 15 秒，偏慢）。

### 1.3 模型管理（一般不用动）
点侧边栏「模型」可以看所有模型的元数据（名称/供应商/标签/定价模式）。新建渠道时模型会自动带出来，通常不用手动建。

## 第 2 章 · 定价（决定收用户多少钱）

**这一步干什么**：定每个模型的调用单价，平台按这个价从用户余额扣费。

### 2.1 模型定价（核心）
1. 侧边栏「系统设置」→ 左侧「计费与支付」→「模型定价」
2. 看到模型价格列表（几千条）
3. 点某个模型那一行，右侧出编辑面板：
   - **计费类型**：按 Token（按用量）/ 按次（固定价）/ 表达式
   - **输入价格**：每百万 token 输入收多少美元
   - **补全（输出）价格**：每百万 token 输出收多少美元
   - 缓存读取/写入价格、图像/音频价格（用得着才填）
4. 改完点「保存」

> 💡 **换算**：1 美元 = 500000 配额单位。新用户默认送 250000 配额 = $0.5。

### 2.2 分组定价（给不同用户不同价）
1. 「计费与支付」→「分组定价」
2. 现在有 3 个组：default（普通）、vip、svip
3. 可以设置每个组的**倍率**——比如 vip 组打 8 折就填 0.8
4. 把用户分到某个组（在「用户」页编辑用户时选分组），他就按那个组的价格计费

### 2.3 额度设置（新用户送多少、充值入口）
1. 「计费与支付」→「额度设置」
2. 关键字段：
   - **新用户配额**：250000（=$0.5，注册就送，让新用户能先体验）
   - **充值链接**：用户买额度的入口（当前 https://ai.yuxin.yun/pay）
3. 【验证】注册一个新账号，登录后钱包余额应该是 $0.5

## 第 3 章 · 配支付收款（让用户能充值）

**这一步干什么**：接入微信/支付宝，让用户能扫码充值。这是最关键也最容易配错的一步。

### 3.1 进支付配置页
侧边栏「系统设置」→「计费与支付」→「支付网关」。里面有 8 个 tab（常规/Epay/Stripe/Creem/Waffo/微信支付/支付宝）。

### 3.2 常规设置（先配这个）
「常规」tab：
- **付款方式**：列出当前启用的支付方式（支付宝 alipay、微信 wxpay、自定义1）
- **充值金额选项**：用户可选的充值档位（$10/$20/$50/$100/$200/$500）
- **最低充值**：单笔最低充多少

### 3.3 微信支付（Native 扫码）
「微信支付」tab，逐项填：
| 字段 | 从哪拿 |
|---|---|
| 商户号 Mchid | 微信商户平台「账户中心」，10 位数字 |
| AppID | 公众号/小程序后台 |
| APIv3 密钥 | 商户平台「API 安全」→ APIv3 密钥，32 位 |
| 商户私钥 | 商户平台下载 apiclient_key.pem |
| 证书序列号 | 商户平台「API 安全」→ 证书管理 |
| 回调地址 | 留空，默认 https://ai.yuxin.yun/api/wechat/notify |

填完保存。
【验证】用测试账号去「钱包」选金额 → 点微信支付 → 应该弹出二维码。

> ⚠️ **当前状态**：微信支付因商户平台 APIv3 密钥被重置暂时不可用，待客户从商户平台取新密钥后恢复（详见微信密钥阻塞记录）。

### 3.4 支付宝（当面付）
「支付宝」tab：
| 字段 | 从哪拿 |
|---|---|
| AppID | 支付宝开放平台应用详情 |
| 应用私钥 RSA2 | 开放平台「接口加签方式」 |
| 支付宝公钥 | 同上「查看支付宝公钥」 |

【验证】测试账号钱包 → 支付宝 → 弹二维码（当前支付宝已实测可出码）。

### 3.5 其他支付（Stripe/Creem/Waffo，用得着才配）
目前都未配置。要接的话按各自 tab 里的提示填 API 密钥即可。

## 第 4 章 · 注册登录与安全（控制谁能进来）

### 4.1 注册开关
「系统设置」→「身份验证」→「基本身份验证」：
- **注册已启用**：开着就能注册新账号（当前开）
- **电子邮件验证**：关了=注册不用验邮箱（当前关，注意有批量注册风险）
- **邮箱域白名单**：限制只能用哪些邮箱后缀注册

### 4.2 人机验证（防机器人，建议开）
「身份验证」→「机器人保护」：
- **启用 Turnstile**：打开后登录/注册要过人机验证
- 需要 Cloudflare 的站点密钥和密钥（去 Cloudflare 免费申请）
- 当前未开启（待客户提供 Cloudflare 密钥）

### 4.3 第三方登录（GitHub/Google 等）
「身份验证」→「OAuth 集成」，6 个 tab（GitHub/Discord/OIDC/Telegram/LinuxDO/微信）。
目前都未配置。要接哪个就在对应 tab 填 Client ID 和 Secret（去对应平台申请开发者应用）。

### 4.4 限流与敏感词
「安全与限制」：
- **速率限制**：限制每个用户每分钟最多调多少次（当前模型请求限流关，但注册登录有 nginx 层限流）
- **敏感词**：开启后，用户发的内容含敏感词会被拦截（当前开，测试词 test_sensitive）
- **SSRF 保护**：防服务器被利用发恶意请求（当前开，别关）

## 第 5 章 · 日常运营（用户/兑换码/订阅/公告）

### 5.1 用户管理
侧边栏「用户」，看到所有账号列表（ID/用户名/状态/额度/分组/角色/邀请信息）。
**常用操作**（点行尾的菜单）：
- **编辑用户**：改密码、调额度、改分组、加备注
- **调额度**：用户"充值未到账"时，手动给用户加额度
- **禁用**：封号（用户立即无法登录和调用）
- **提升**：把普通用户改成管理员（谨慎，仅超管能做）
- **删除**：销号

> 💡 处理"我充钱了没到账"工单的标准流程：①在「用户」搜到这个用户看额度变动 ②看他的「使用日志」确认调用 ③确认是平台问题就手动补额度或发兑换码。

### 5.2 兑换码（发卡密）
侧边栏「兑换码」→「创建代码」：
- **名称**：这批码的名字（如"新用户福利"）
- **额度 (USD)**：每张码值多少美元
- **过期时间**：永不/1月/1周/1天
- **数量**：一次生成几张（1-100）
生成的码在列表里复制发给用户。用户在「钱包」页底部输入码兑换。
【验证】自己建一张码，用测试账号在钱包兑换，余额应增加。

### 5.3 订阅套餐
侧边栏「订阅」，管理套餐（当前有"基础套餐 $99/月，含 $15 额度"）。
点「创建套餐」可新建：标题、价格、含额度、有效期、升级分组等。
> ⚠️ 注意：当前"基础套餐 $99 含 $15 额度"价格高于额度（$99 买 $15），疑似配置错误，建议核对。

### 5.4 发公告
「系统设置」→「控制台内容」→「公告」→「添加公告」。发布后用户登录就能看到。

### 5.5 配置首页能看什么
「系统设置」→「站点与品牌」：
- **系统信息**：改站名、Logo、页脚、用户协议、隐私政策
- **顶部导航**：控制首页顶部显示哪些入口（主页/模型广场/排行榜/文档）
- **侧边栏模块**：控制用户侧边栏显示哪些功能（19 个开关）

## 第 6 章 · 监控与故障排查

### 6.1 看系统状态
侧边栏「系统信息」（仅超管可见）：
- 实例状态（CPU/内存/存储/版本）
- 版本号（当前 1.2.22-yuxin）
- 系统任务（渠道批量测试、模型更新等）

### 6.2 常见问题速查
| 用户反映 | 你去哪看 | 大概率原因 |
|---|---|---|
| 调 API 报 503 | 「渠道」看渠道状态 | 渠道被自动禁用（上游故障）→ 手动启用或换渠道 |
| 充钱没到账 | 「用户」查额度 + 「使用日志」 | 支付回调延迟 → 手动补额度 |
| 登录不上 | 「用户」查状态 | 密码错/被禁用/触发限流 |
| 某个模型用不了 | 「模型定价」+「渠道」 | 该模型没定价或没在任何渠道启用 |
| 提示额度不足 | 「用户」查余额 | 真的没钱了 → 引导充值 |

### 6.3 智能调度（auto 模型）
「系统设置」→「模型与路由」→「智能调度」：
- 用户调用时把 model 写成 `auto`，平台自动从候选池选最优模型
- 当前候选池：deepseek-v4-flash / qwen3.6-flash / glm-5.1
- 每次实际用了哪个模型，响应头 `X-Yuxin-Model` 会标明，按实际模型计费

## 附录 B · 给 0 基础的几个重要提醒
1. **改任何设置后，记得点页面右上/底部的「保存」**，不保存不生效。
2. **支付/密钥类字段**在界面上显示为空白是正常的（安全设计，留空=不改动原值）。
3. **连续登录失败会触发限流**（429），等 10-15 分钟再试。
4. **配额单位换算**：1 美元 = 500000 配额。新用户送 250000 = $0.5。
5. **渠道是模型的来源，定价是收钱的标准，支付是充值的入口**——这三样配好，平台就能跑起来。
6. 遇到拿不准的，先看第 6 章故障速查，再不行联系技术。
